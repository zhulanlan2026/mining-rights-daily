## 3. 会话缓存（短期记忆）怎么存——定案

这里说的「会话缓存」= LangGraph **Checkpoint（短期记忆）**，不是 RAG，也不是 3.0 长期记忆。

### 定案

| 环境 | Checkpoint 存哪里 | 说明 |
| --- | --- | --- |
| **2.0 商品默认 / compose / 联调接近生产** | **PostgreSQL**（LangGraph Postgres checkpointer） | 可多进程、可备份、可与运维统一 |
| **本机快速开发且未起 Postgres** | **SQLite 降级**（现有 `AsyncSqliteSaver`） | 用环境变量切换；文档标明「非商品默认」 |
| **RAG 向量** | **同一 PostgreSQL 实例 + pgvector** | 与 Checkpoint **同库不同表**；语义分离，禁止混在一张「会话表」里 |
| **Redis** | 2.0 **不用** | 留给 3.0 高并发 |

### 配置约定（实施时遵守）

- `AGENT_CHECKPOINT_BACKEND=postgres|sqlite`（默认生产 `postgres`，本地可 `sqlite`）
- Postgres：`DATABASE_URL`（Checkpoint + RAG 共用连接串，表前缀或 schema 分开，例如 `checkpoints_*` vs `rag_*`）
- SQLite：保留现有 `AGENT_CHECKPOINT` / `--checkpoint` 文件路径

### 验收口径

- 同一 `thread_id` 在 Postgres 下续聊成功。
- 从 SQLite 迁到 Postgres **不要求**自动迁移旧本地文件；文档写清「开发库与生产库分开」。
- 进程重启后，Postgres 中的会话仍可续聊；SQLite 文件仍在则本地也可续聊。

## 4. 路由：在 1.0 上扩展，不替换

1.0 四分支保留：`daily` / `single` / `follow_up` / `clarify`。

2.0 **新增**一条（名称可定为 `complex_analysis`）：

- 适用：趋势分析、技术分析、政策背景、需要历史研报/日报的问题。
- 路径：**Skill 选择（若需要）→ RAG 召回 →（按需）MCP 工具 → 写作**。
- 与 `daily` 的边界：用户明确「今日/日报/简报」走 `daily`（固定子图，不先 RAG）；分析类、对比类、政策类走 `complex_analysis`。

意图识别仍：**规则优先，LLM 可选**；无密钥时规则 + clarify，不阻塞。

## 5. 2.0 要做的升级（含 1.0 应加强项）

### 5.1 重试（1.0 缺，2.0 补）

- LLM 与 MCP 外层：`max_retries=3` + 指数退避。
- **可重试**：超时、连接失败、HTTP 5xx、限流。
- **不可重试**：参数校验失败、业务 DomainError、4xx（除 429）。
- 另设 **单次用户请求的工具总时长预算**，避免 ASX 类慢下载 ×3 拖垮整次会话。
- 耗尽后走 1.0 已有降级文案「未获取到数据」，不中断主流程。

### 5.2 RAG（2.0 新能力）

- 语料：历史日报、内部研报、行业政策（可溯源：标题、来源、日期、片段）。
- 挂在 `complex_analysis`；**不强制**插入日报固定子图（避免拖慢「今日简报」）。
- 引用必须可溯源；写进正文的数字仍受 1.0 幻觉防线约束。

### 5.3 Skill 自动发现（1.0 写死路径 → 2.0 升级）

- 扫描 `skills/*/SKILL.md`，读 L1 元数据注册。
- **日报子图**：继续固定绑定 `mining-daily-report`，不改成模型自由点菜。
- **复杂分析**：按意图/菜单按需加载对应 Skill。
- 验收：新增一个分析类 Skill 目录即可被发现，无需改路由代码表。

### 5.4 正式数据源（商品化前置，独立数据线）

- 目标：替换「合成 NI 43-101」「bundled 参考价」作为**对外默认**。
- 实施允许 **正式源优先，失败回退 1.0 样本**，简报必须标明实际采用的来源。
- 2.0 启动前在任务书中**点名**价格源、储量 PDF 来源、新闻策略（可继续 ASX + RSS + 清洗）；未定点前，数据线可并行调研，但不算 2.0 编排验收通过。

### 5.5 入口层

- **2.0 不强制迁 FastAPI**。保留 1.0 的 CLI / SSE / 企业微信。
- 若后续要统一 HTTP API，单列任务，不塞进「RAG+重试」同一里程碑。
